# 網羅の確認（段階3）

## 実行のしかた

```
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/banto.py" --project <対象プロジェクト> coverage
```

Windows では `python3` を `python` に置き換える。同期（`sync`）のたびにも網羅表は更新される。

## 出るもの

- `banto/coverage/README.md`：網羅表。項目ごとに「該当（必要／該当／不要の候補／判断済み）」と「充足（充足／情報不足）」、詳細、根拠
- `banto/coverage/<項目ID>.md`：不足票（何が・どこで・いくつ足りないか、埋め方、担当）と、不要の候補の確認票
- `banto/manual/<項目ID>.md`：人が書く節・表のひな形（システム概要、画面一覧など）。ひな形のままなら情報不足

## 手順

1. 網羅表を開き、文書ごとに要点を伝える（充足・情報不足・不要の候補の数、重要な不足）
2. **不要の候補**：根拠（何が見つからなかったか）を示し、本当に不要かをユーザーに聞く。決まったら
   - 不要：`banto decide --item <ID> --exclude --by <名前> --reason "<理由>"`（設計書に「対象外（理由）」と載る）
   - 必要：`banto decide --item <ID> --include --by <名前> --reason "<理由>"`
3. **情報不足**：不足票の「埋め方」に従う
   - 台帳の列（論理名・説明・期待結果など）：既存の設計書やDBのコメントから取り込めるなら sources.json を直して同期。取り込めなければ台帳MDに書く
   - 人が書く節・表：`banto/manual/<ID>.md` に書き、書き終えたら frontmatter の `status` を `confirmed` にする
   - コードから下書きできるもの（画面一覧・API一覧・クラス一覧など）は `extractor` エージェントに下書きさせ、**（推定）** と書き添えて人に確かめてもらう
4. 埋めたら同期して、充足になったかを確かめる

## ルール

- 不要かどうかを決めない。手がかりは機械的な検索で、見落としもある
- 推定で埋めた値は、人が確かめるまで「（推定）」を外さない

## 防ぐ失敗

設計書の章が抜けたまま提出し、「帳票の章が無いのは対象外だからか、書き忘れか」に答えられない。
