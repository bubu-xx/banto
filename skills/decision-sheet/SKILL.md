# 判断票

判断票（`banto/drifts/DRF-xxxx.md`）を材料に、人が判断できるよう説明する。**判断するのは人。** あなたは番頭であって主人ではない。

## 判断票に載っているもの

1. **何がずれているか**：台帳と各情報源の値・書かれ方・場所。台帳と違う情報源に「≠」
2. **つながり**：上流（設計書）、実物（DDL・コード・実行結果）、下流（テストで触れている箇所）
3. **経緯**：設計書の注意書き、関係ファイルの変更履歴、情報源が自ら書いた対象範囲、許容済みの差、以前の判断
4. **選択肢と影響**：値ごとに「これを正とすると、どれを直す必要があるか」と、そのためのコマンド

## 手順

1. `banto/drifts/README.md` を読み、未判断を **重要度 → グループ** の順に示す。グループは「同じ規則でまとめて判断できる候補」なので、件数の多いグループから一括判断を提案すると速い。
2. ユーザーが見たいずれの判断票を開き、上の4点を短く要約する。選択肢は判断票のとおりに並べ、影響（直す必要がある情報源）を必ず添える。
3. 意味の確認が要るとき（例：アプリは10桁固定、DBは20桁。どちらが業務上正しいか）は、関係するコードや文書を読んで材料を足す。足した材料は判断票の「補足」欄（`<!-- banto:notes -->` の下）に **（推定）** と書いて残す。この欄は同期しても消えない。件数が多いときは `matcher` エージェントに任せる。
4. ユーザーが決めたら `/banto:apply-decision` で記録する。

## ルール

- **おすすめを言わない。** 「多数派だから」「設計書だから」で正を決めない。ユーザーに聞かれたら、各選択肢の影響と、判断に足りない情報（誰に確認すべきか）を答える
- 推定は推定と書く。確認していないことを事実として書かない
- 判断票のファイルは、補足欄以外を手で書き換えない（次の同期で上書きされる）

## 防ぐ失敗

声の大きい人や、たまたま開いた資料が「正」になり、その理由が残らない。

例：「長さ：DDL（PostgreSQL） が他と異なる」10件を、根拠を確かめずに「全部20に揃える」と直す。判断票では、PostgreSQLだけが `TEXT`（長さ無制限）であること、どのテストが触れているかが並ぶので、「方言差として許容」か「揃える」かを理由つきで選べる。
