# banto

> 帳簿はすべて頭に入っている。合わないところを見つけたら、両方の言い分と経緯を揃えて差し出す。決めるのは、あなた。

banto（番頭）は、システム開発の成果物（要件・基本設計・詳細設計・ソースコード・テスト）の関係をMDで完全に管理し、
それぞれの中身がずれたときに「何をどう直すか」を人が判断するための材料を揃える仕組みです。

- **MDが帳簿**：要件 → 設計 → コード → テストのつながりを、IDの鎖としてMDに持つ
- **合わないところを差し出す**：取り込み時も運用中も、ずれを見つけたら判断票にして人に見せる
- **決めるのは人**：bantoはどれが正かを決めない。人の判断と理由をMDに記録し、次の判断の材料にする
- **提出はExcelで**：MDから設計書やテスト仕様書をExcelに清書し、レビュー表で指摘を受けて往復する

詳しくは [docs/concept.md](docs/concept.md)（構想）と [docs/spec.md](docs/spec.md)（規約のたたき台）を参照。
